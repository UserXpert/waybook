# Browser tests

`npm run e2e --workspace=@waybook/app` runs the Waybook booking, calendar and tenant-access tests on desktop and mobile. It requires a production build and three **disposable local** PostgreSQL databases. Set `WAYBOOK_CONTROL_DATABASE_URL`, `WAYBOOK_NORDIC_STUDIO_DATABASE_URL` and `WAYBOOK_COPENHAGEN_PHYSIO_DATABASE_URL` to those databases, with names beginning `waybook_e2e_`; run `npm run waybook:db:migrate`, `npm run waybook:db:seed` and `node --import tsx scripts/seed-waybook-e2e.mts` first. The CI workflow shows the complete setup. Never point the seed commands at production data.

`npm run waybook:test:hold-lifecycle` exercises concurrent holds and expiry against a separate disposable local fixture. Set `WAYBOOK_LOCAL_PERF_DB_URL` to a local database whose name starts with `perf_` or `waybook_test_`, and `WAYBOOK_ISOLATED_APP_URL` to a local app configured to use that database. Set `WAYBOOK_TEST_TENANT_ID`, `WAYBOOK_TEST_LOCATION_ID`, and `WAYBOOK_TEST_PREFLIGHT_SERVICE_ID` to an active tenant, online location, and public service in that fixture. `WAYBOOK_TEST_TENANT_ROUTE` defaults to `nordic`. Set `WAYBOOK_TEST_FORCE_HOLD_RACE=1` to run the delayed-insert variant. The test creates temporary records and must never target a real tenant database.
